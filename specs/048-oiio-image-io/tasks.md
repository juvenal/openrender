## Conventions

- **Paths** are relative to `$WT` unless absolute. **Line numbers** are master `278b0394`; re-locate by text if one moved.
- **`[P]`** marks a task that touches files no other open task of its phase touches. A `CMakeLists.txt` that several tasks register into is edited by one task at a time. Without `[P]`, a task depends on the task before it.
- **Story labels**: `[US1]` read images through OIIO with the same samples; `[US2]` nothing changes unless OIIO is asked for (selection, FR-013, FR-014); `[US3]` bake textures through OIIO; `[US4]` the `oiio` display driver; `[US5]` OIIO enters the build without breaking the architecture or the platforms. Phases 1 and 9 carry none.
- **Build, test, vcpkg and measurement tasks** go through `~/.claude/bin/cpujob <label> <command>`: `-j4` at most on macOS, **never `-j8`, never a bare `-j`**, `-j2` for the determinism sweep and on the Linux host, `VCPKG_MAX_CONCURRENCY=4` on every vcpkg or configure run. Long jobs run in the background with the log redirected. **Every `ctest` command in this file runs as `~/.claude/bin/cpujob <label> ctest ...`** (the label is not repeated in each task, and a bare `ctest ...` below always means that). **A test binary is never run directly.** The only non-ctest programs run (always through `cpujob`) are tools: the fixture generators, `orender`, `otexmake`, `tools/capture_baseline.sh`. Every build, test, configure, vcpkg and measurement task waits for the coordinator's go-ahead before it runs.
- **Build trees**: `build/` is the OIIO-off tree and uses the private base install directory `~/.cache/vcpkg-installed/openrender-048-base` (quickstart, "Build trees"); `build-oiio/` is the OIIO-on tree and uses the derived `~/.cache/vcpkg-installed/openrender-oiio`. **Neither is ever configured against the shared `~/.cache/vcpkg-installed/openrender`.** Every task that runs `cmake -S/-B` (a configure) or vcpkg runs `tools/vcpkg_shared_guard.sh before` first and `... after` last (written by T002); a changed checksum of the shared tree's `vcpkg/status` or `vcpkg/manifest-info.json` **stops the work** and is reported.
- **Remote**: `H=juvenal@ubuntu-2404-desktop.v2-labs.io`, per-spec tree `R=/home/juvenal/Projects/Development/CLI/openrender-048`, OIIO prefix work in `~/oiio-048`, always written `"${H}:${R}/..."` (zsh reads `$H:path` as a modifier). `ssh` works over WARP, `ping` does not. **Only `${R}` and `~/oiio-048` are touched on the host; never `openrender`, `cellar`, `shrimp`, `openrender-029` or `openrender-038`.** Sync recipe: `tools/sync_linux.sh` (T003): `rsync -rlpc -0 --files-from=<list from git ls-files -z --cached --others --exclude-standard>`, a `manifest.sha256` made on the Mac, verified remotely with `sha256sum -c --quiet`. The sync does not delete: a retired file is removed by an explicit `ssh "${H}" "rm -f ${R}/<path>"` named in the task that retires it. Remote builds: `ssh "${H}" "cd ${R} && CPUJOB_TIMEOUT=7200 ~/.claude/bin/cpujob 048-lx-<n>-build cmake --build build -j2"`; tests: `... ~/.claude/bin/cpujob 048-lx-<n>-test ctest --test-dir build -LE determinism-sweep -j2 --output-on-failure"`.
- **Tolerance**: none, anywhere (FR-021, plan "Tolerance"). Every parity comparison is exact, **except the render-equivalence metric of US3-3** (`ImageIO_BakeRender`: the visual block-average metric at the default parity threshold 20, approved 2026-11-14), which also reports exact identity and is backed by the exact tag-and-sample comparison of `ImageIO_BakeParity`. A test that finds a difference stops the work and goes to the maintainer; it is never widened, skipped or disabled.
- **Where the parity tests run (FR-021, SC-008)**: in every build that has OIIO, on macOS (vendored) and on the Linux validation host (prefix build). CI does not run them in 048; no CI job enables OIIO (P-Q11), and `ImageIO_CiHasNoOiio` keeps it that way.
- **Hooks**: the optional `speckit.git.commit` hooks (before and after tasks and implement) are declined. Nothing is committed, merged or pushed by an agent. `git add` is allowed; each checkpoint stages that phase's files.
- **Stops**: a **TEST-APPROVAL** task follows the tests of a phase and shows them; a **PAUSE** task is one named maintainer approval (the agent writes the proposal or the diff, reports, and does not apply it, or start any task that depends on it, until approved); a **CHECKPOINT** closes every phase with a report, the maintainer commits, and the next phase does not start on its own.
- **Checkpoint architecture step**: every checkpoint from Phase 2 on runs `ctest --test-dir $WT/build -L architecture` (and `build-oiio` once it exists) through `cpujob`, which must pass with `tests/architecture/allowlist.txt` unchanged (`git diff --stat -- tests/architecture/allowlist.txt` empty).
- **Records**: every checkpoint appends to `specs/048-oiio-image-io/validation.md` (commands, counts, what is still red and why) and stages the phase's files.
- **Never**: widen a threshold, disable or skip a test, edit an approved test or reference outside its PAUSE (the 018 `tests/unit/image_input/fixtures` and their references are never edited), re-capture a reference to make a test pass, add an allowlist line, delete or rename anything (FR-001; deleting even a scratch file or directory outside `/tmp` is asked about first), edit `CLAUDE.md`, `NEWS.md` or `ChangeLog.md` (T125 writes the drafts; applying them is a [MAINTAINER] step), run vcpkg or a configure against the shared install directory, write a task that depends on the merge, write the hash of this spec's own merge commit or a `Closes #NN` line. No colour conversion is ever applied and no OIIO type crosses `orImageIO.h`.
- **Legacy defects are not fixed here**: GitHub #171 (RLE `.hdr` decode, `RGBE_ReadPixels`) and #172 (the `rgbe` display driver's `rgba` stride) are cited by `D-RGBE-RLE`, the display contract and `DEVNOTES_DETAILS/IMAGE_IO.md`. No task changes the legacy RGBE decoder or driver.

## Implementation strategy
