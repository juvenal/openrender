## Conventions

- **Line numbers** are master `d6910bd0` (unchanged by `01501f10` for the files this spec touches), the base after the Phase 0 merge, not the pre-merge worktree. Re-locate by text if a line moved.
- **`[P]`** marks a task that touches files no other open task of its phase touches. A `CMakeLists.txt` that several tasks register into is edited by exactly one sequential task. Without `[P]`, a task depends on the task before it.
- **Story labels**: `[US1]` to `[US7]` on story phases (2 to 7). Phases 0, 1, 8 and 9 are setup, foundational and polish phases and carry none; their descriptions name the story in words.
- **Build, test and tool runs** go through `~/.claude/bin/cpujob <label> <command>`, never above `-j4` (Linux, the determinism sweep and the capture target at `-j2` or less). A test binary is never run directly. Every build or test task waits for the coordinator's go-ahead. `precomp`, `oshader` batches and the capture target are runs too, so they use `cpujob`.
- **Hooks**: the optional `speckit.git.commit` hooks (before and after tasks and implement) are declined. Nothing is committed, merged or pushed by an agent. `git add` is allowed and each phase's record task stages that phase's files.
- **Stops**: a **TEST-APPROVAL** task is a stop (it opens each phase; in Phase 1 it follows the tests it approves, which have to exist to be shown). The agent writes the listed material, reports it to the coordinator and does not start the phase's implementation tasks until the maintainer approves. A **CHECKPOINT** closes every phase and ends with a report; the next phase does not start on its own.
- **Remote**: `H=juvenal@ubuntu-2404-desktop.v2-labs.io`, `R=/home/juvenal/Projects/Development/CLI/openrender-038`, always written `"${H}:${R}/..."` (zsh reads `$H:path` as a modifier). Commands are in quickstart.md section 3.
- **Never**: widen a threshold, disable a test, edit an approved test or reference outside its TEST-APPROVAL stop, add an allowlist line, edit `CLAUDE.md`, write a task that depends on the merge of 038, write the hash of 038's own merge commit or a `Closes #NN` line (the base references `628d6747`, `d6910bd0` and `01501f10` are allowed). Registry entries move to Resolved with "spec 038" and the date the task is run.
- **Checkpoint architecture step**: every checkpoint runs `ctest -L architecture`, which must pass, and then `ctest -L or038_red`, whose result is compared with the expected red set of the table below. `or038_red` is the temporary label of the new `cmake -P` checks that are still red; the task that turns a check green changes its label to `architecture` (stated in that phase's TEST-APPROVAL stop). Phase 9 verifies that no test carries `or038_red`.
- **Records**: every checkpoint appends to `specs/038-scene-interface-untangle/validation.md` (commands, counts, what is still red or disabled and why).
