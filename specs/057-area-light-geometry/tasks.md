## Conventions

- **Line numbers** are master `278b0394`. Re-locate by text if a line moved.
- **`[P]`** marks a task that touches files no other open task of its phase touches. A task that registers a target or test in a shared `CMakeLists.txt` or `.cmake` file (`tests/arealight/CMakeLists.txt`, `tests/visual/arealight-scenes.cmake`, `tests/shading_contract/CMakeLists.txt`) carries no `[P]`: those edits are made one task at a time. Without `[P]`, a task depends on the task before it.
- **Story labels**: `[US1]` to `[US11]` map to the eleven user stories of spec.md (US1 binding, US2 area sampling of polygons/meshes/subdivision, US3 light-surface execution and the estimator, US4 soft shadows on three hiders, US5 controls, US6 quadrics, US7 patches and NURBS, US8 photon emission, US9 deprecation and the old/new agreement, US10 nothing else changes, US11 documents). Setup, checkpoint, validation and sync tasks carry none.
- **Build, test and render jobs** go through `~/.claude/bin/cpujob <label> <command>`: `-j4` at most on macOS, `-j2` for the determinism sweep, for the noise sweeps and on Linux; never `-j8` or a bare `-j`. Long jobs run in the background with the output redirected to a log under `$WT/build/`. A test binary is never run directly (a hung one has no timeout): every run is `ctest` (or a script a ctest entry or a task runs through `cpujob`). The stage rule applies at implementation time too: **before the first build or test job of a phase, the implementing agent asks the coordinator**; each job is named in its task so the coordinator can approve it.
- **Environment for renders** (this worktree has no `openrender/` deploy tree): the visual suite's build-tree paths, `SHADERS=$WT/build/shaders ORENDERHOME=$WT/build/tests/visual/_home DISPLAYS=$WT/build/src/display/file:$WT/build/src/display/rgbe:$WT/build/src/display/framebuffer GEOMETRIES=$WT/geometry` (quickstart.md).
- **Red-first**: a test that cannot compile yet lives in its own executable inside `if(OPENRENDER_057_RED_TESTS)` in `tests/arealight/CMakeLists.txt` (default OFF, defined by T008), so it never breaks the build or another test; its red evidence is the build failure of that one target (`cmake --build $WT/build --target <t>` with the option ON, then the option back OFF; no second build tree). The task of the phase that creates the API moves the test's definition out of the block. A test that compiles (a render pair, a script, a scene check) is registered at once and its red evidence is a failing run. A test is **approved** at its phase's **TEST-APPROVAL** pause (after the red evidence, before the first implementation task: constitution III); a change to an approved test or reference is a PAUSE that shows the diff first. Before the TEST-APPROVAL the agent may correct a test it wrote, recording the reason and re-recording the red evidence; it never changes a test to turn it green. Phase 9 has no red-evidence task (its agreement test has no red state) and so no TEST-APPROVAL; its scenes and threshold are approved at the agreement PAUSE.
- **Test-local shaders** (probe lights and surfaces) live in `tests/arealight/shaders/*.sl` and are compiled as build steps (`.rslo` always, `.slo` with the JIT) into `$WT/build/tests/arealight/shaders`, as `tests/shading_contract/CMakeLists.txt` does for its contract shaders. **No shader is added to `shaders/`**, so neither the 137-shader count nor `tests/shaders/references` nor either `shaders.sha256` changes (FR-021).
- **Probe tolerances** are computed, not tuned: `tools/probe_expected.py` (T059's first use) integrates the closed form and the single-sample variance of the estimator by dense quadrature, and a probe's tolerance is `4 * sigma_1 / sqrt(n)` for the sample count `n` (4 standard errors), written into the scene header. A tolerance is fixed when the test is written and approved at the checkpoint; it is never widened. Image-test thresholds (visual, parity, agreement) are fixed **after** the scene's own noise is measured with the visual-test noise method (box filter, `jitter 0`, only the light's stream varied by changing its handle), recorded in the test's comment, and shown in a PAUSE before they take effect.
- **Pixel probes** reuse `tests/visual/test_pixel_probe.cpp` and the registration style of `tests/visual/volume-scenes.cmake` / `volume-probes.cmake`; the new registrations live in one new file `tests/visual/arealight-scenes.cmake` included from `tests/visual/CMakeLists.txt` with one `include()` line (as spec 056 did), new scenes in `examples/rib/tests/arealight-*.rib` generated by `specs/057-area-light-geometry/tools/gen_scenes.py` (checked in), references in `examples/rib/tests/references/`.
- **Formatting**: run `clang-format` with the repo's `.clang-format` on an edited source file **only if the file was clang-format clean before the edit** (check with `clang-format --dry-run` on the unedited file first); never reformat a file that was not clean.
- **Hooks**: the optional `speckit.git.commit` hooks (before and after tasks and implement) are declined. Nothing is committed, merged or pushed by an agent. `git add` is allowed; each checkpoint stages that phase's files. The 033 sync's merge is the maintainer's (S02).
- **Stops**: a **TEST-APPROVAL** task follows each red-evidence task (Phases 1-8, 10, 11) and holds the phase until the maintainer approves the tests. A **PAUSE** task is one named maintainer approval: the agent writes the proposal (a diff, a file under `specs/057-area-light-geometry/tools/proposed/`, or images and numbers) and reports; it does not apply it, or start a task that depends on it, until the maintainer approves. A **CHECKPOINT** is the end of a phase: report, stage, stop. The maintainer commits; the next phase starts only afterwards.
- **Remote** (Linux, GCC 13 `-Werror`): `H=juvenal@ubuntu-2404-desktop.v2-labs.io`, `R=/home/juvenal/Projects/Development/CLI/openrender-057`, always written `"${H}:${R}/..."` (zsh reads `$H:path` as a modifier). ssh works over WARP; ping does not. Only `${R}` is touched on the host: **never** `openrender`, `cellar`, `shrimp`, `openrender-029` or `openrender-038` (nor another spec's tree). Sync recipe (`tools/sync_linux.sh`, T005): `rsync -rlpc -0 --files-from=files.list $WT/ "${H}:${R}/"` with `files.list` from `git -C $WT ls-files -z --cached --others --exclude-standard`, a `manifest.sha256` made on the Mac, then `ssh "${H}" "cd ${R} && sha256sum -c --quiet manifest.sha256"`. Remote jobs: `ssh "${H}" "cd ${R} && CPUJOB_TIMEOUT=7200 ~/.claude/bin/cpujob 057-pN-lx-build cmake --build build -j2"` and `... ~/.claude/bin/cpujob 057-pN-lx-test ctest --test-dir build -L arealight -j2 --output-on-failure"`. The sync does not delete: a removed file is removed with an explicit `ssh "${H}" "rm -f ${R}/<path>"` named in the task that removes it.
- **Never**: widen a tolerance or threshold, disable a test to get a green result, edit an approved test or reference outside its PAUSE, re-capture an existing reference (SC-007), add an allowlist line (FR-029), edit `CLAUDE.md` (T144 writes a draft the maintainer applies), write a task that depends on the merge (no post-merge steps, no merge-commit hash, no `Closes #NN` line: the maintainer writes that in the merge commit), touch GitHub #169's defect (it is not fixed here) or #163/#166, delete anything without asking.
- **Checkpoint architecture step**: every checkpoint runs `ctest --test-dir $WT/build -L architecture` (through `cpujob`) and it must pass with `tests/architecture/allowlist.txt` and `ribvector-core-residual.txt` unchanged. The full suite is re-run at the checkpoints marked FULL.
- **Records**: every checkpoint appends to `specs/057-area-light-geometry/validation.md` (commands, counts, what is still red and why) and stages the phase's files.
