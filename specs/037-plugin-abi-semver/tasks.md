## Standing rules (apply to every task)

**Builds and tests (marked [RUN])**:
- A task is marked **[RUN]** when **any step of it** configures, builds, tests, installs, renders (`orender`) or runs a script or command that does; edit-only tasks carry no marker and run nothing. If a task mixes editing with such a step it is marked [RUN] and its run steps are the ones that wait for the coordinator.
- The implementer asks the coordinator before each [RUN], then runs it through `~/.claude/bin/cpujob <label> <command>`: one job at a time machine-wide, `nice -n 19`, at most `-j4`. The determinism sets, the TSan tree and every Linux job use `-j2`.
- Long jobs go in the background with output redirected to `build-037-logs/<label>.log`. Wait for the completion notice; do not poll.
- Never run a test binary directly (a hung one has no timeout). Never use `-j8`, a bare `-j`, or a count above 4. A plain `cmake --build` / `ctest` / `cmake --install` / `orender` line below always means the `cpujob` form (`cpujob <label> orender ...` for a render run by hand).
- Never widen a test threshold, never disable a test to get a green result, never regenerate a reference to get a green result.

**Checkpoint procedure** (referenced as CP-a to CP-c by every phase's last task):
- **CP-a build**: `cpujob 037-pN-build cmake --build build --config Release -j4`. Clean under `-Werror`.
- **CP-b suite**: `cpujob 037-pN-suite ctest --test-dir build -LE determinism-sweep -j4 --output-on-failure`, then `cpujob 037-pN-abi ctest --test-dir build -L plugin_abi -j4 --output-on-failure`. Expected: the Phase 1 pass list (`specs/037-plugin-abi-semver/tools/baseline-pass-list.txt`) plus the tests enabled so far; the **known-red tests** below are the only allowed failures. A test from the flaky set (memory `reference_ctest_flaky_tests.md`: `ImagerRegressionRender`, `Parity_transparency-matte-aov`, `Parity_depthdefault`, `ShadingParity_AmbientAccumulation`) is re-run alone before it is written off; `ShadingParity_AmbientAccumulation` is a real heap bug, compare it with the Phase 1 run.
- **CP-c architecture**: `cpujob 037-pN-arch ctest --test-dir build -L architecture --output-on-failure` over a **complete** build, plus the full report `cpujob 037-pN-arch-report build/tests/architecture/archcheck --source-dir . --build-dir build --config tests/architecture`. Record the `ALLOWED`, `METRIC` and `RESULT` lines in validation.md. Expected per phase: the deletions that phase makes, no `STALE`, no `VIOLATION`, no `unclassified:`.
- **Scene identity**: the visual and shading-parity suites inside CP-b, plus `DisplayAbi_PixelsIdentical`, `DisplayAbi_LegacyPixelsIdentical` and `ProceduresAbi_Scenes` (green since Phase 1), are the evidence that no image changed (FR-030, FR-021). Any difference stops the phase.
