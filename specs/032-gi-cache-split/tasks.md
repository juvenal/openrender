## Standing rules (apply to every task)

**Builds and tests (marked [RUN])**:
- Ask the coordinator before each [RUN], then run it through `~/.claude/bin/cpujob <label> <command>`: one job at a time machine-wide, `nice -n 19`, at most `-j4` on macOS; the determinism sweep and every Linux job run at `-j2`. Every tool run goes through it too: `oshader`, `archcheck`, `image_manifest.sh`, a scratch link line, `nm`/`dyld_info` on a large binary. Quick, light commands (`git`, `grep`, `diff`, `ls`) need no lock.
- Run `df -h /Volumes/Projects` before every heavy job (a configure+build, a copy of a build tree, a sweep). Stop and report below 2 GB free.
- Long jobs run in the background with output redirected to `build-logs/<label>.log`; wait for the completion notice, do not poll. Exit 124 is a timeout: report it (a first Linux build may need `CPUJOB_TIMEOUT=7200`; ask).
- Never run a test binary directly (a hung one has no timeout). Never use a debugger. Never `-j8`, a bare `-j`, or a count above 4. A plain `cmake --build` / `ctest` line below always means the `cpujob` form, and so does every `cmake -B` configure (it can trigger vcpkg; use the environment the coordinator gives, never invent `VCPKG_ROOT`).
- Linux is reached over ssh in the per-spec tree `~/Projects/Development/CLI/openrender-032` with the remote `~/.claude/bin/cpujob` at `-j2`. **Never touch `~/Projects/Development/CLI/openrender`, `cellar`, `shrimp` or another spec's tree.**

**Test gate (TG)**, defined once, used from Phase 3 on:
1. Delete the phase's allowlist lines by key (never by number) and fix the section-header counts. [RUN] `$CJ 032-pN-red-arch ctest --test-dir $W/build -L architecture --output-on-failure`: it must fail with exactly the `VIOLATION` lines of the deleted keys and nothing else. Record the output in `validation.md` §2.
2. Add the phase's sub-checks to `GI032_BOUNDARY_CHECKS` (the list `GiSplit_Boundary` reads) and show them red.
3. A new test enabled by the phase is moved out of the `OPENRENDER_032_RED_TESTS` block only in the implementation task that makes it buildable; its red reason was recorded at Phase 2 (T-A2, T-C, T-D, T-E) and is not re-run.

**Checkpoint procedure**, defined once:
- **CP-a build**: `$CJ 032-pN-build cmake --build $W/build --config Release -j4`. Clean under `-Werror`; it builds every target, `ribVector` included.
- **CP-b suite**: `$T/image_manifest.sh stamp $W/build`, `$CJ 032-pN-suite ctest --test-dir $W/build -LE determinism-sweep -j4 --output-on-failure`, then `cp $W/build/Testing/Temporary/LastTest.log $W/build-logs/pN.LastTest.log` before the next ctest run. Record the `ALLOWED`, `METRIC` and `RESULT` lines in `validation.md` §1. `NOTE metric ... < baseline` lines are notes, not failures (the metric rows are lowered in Phase 6). Run it before every phase report (agent rules).
- **CP-d images**: `$T/image_manifest.sh record $W/build` against `tools/baseline-images-macos.sha256` through `diff` with the noise list `tools/baseline-image-noise-macos.txt`, and `$T/image_manifest.sh diffs $W/build-logs/pN.LastTest.log` against `tools/baseline-diffs-macos.txt`. **Thresholds and references**: never widen a threshold, never disable a test (other than the red-first option block), never regenerate a reference image, never re-record `tests/shading_contract/replay/*`, never edit an approved reference. The new references under `tests/gi_split/reference/` and `tests/preview/reference/` are recorded only on the unmodified tree (Phase 1), and only again before Phase 3 begins, and only if PAUSE 1a changed a mask.
