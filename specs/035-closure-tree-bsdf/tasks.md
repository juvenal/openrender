## Conventions

- **Line numbers** in plan.md, research.md and the contracts are master `b9dec4e5`. After the sync they are stale: re-locate by text and record the new ones (Phase 0).
- **Master syncs**: two, both maintainer or coordinator steps (an agent never merges, commits or pushes). The first is the opening task of Phase 0, the second is in Phase 5 before the closing validation. The **first** is conflict-free apart from the spec files (the branch has no source change yet; master `4ee81900` has #199, #200, #197, #115 and #204). The **second** may conflict in `src/libshader/shading/shading.{h,cpp}`: the bug-fix queue after #205 is #16+#201, #212, #211, #113 (JIT `phong`), #203 (`jitParameterFinish`), #209, #208, #210, #169, #156 in that order, and #113 and #203 are in the shading area, so expect them at the second sync (or at any further one); spec 054 also edits `shade()`. Conflicts are resolved in the working tree only and staged; the maintainer commits the merge. A further sync at any phase boundary the coordinator asks for runs the same three steps as the Phase 5 sync (re-read, re-apply, rebuild and re-test).
- **Build, test and render jobs** go through `~/.claude/bin/cpujob <label> <command>`: `-j4` at most on macOS; `-j2` for the determinism sweep, the noise or timing runs and everything on Linux; never `-j8` or a bare `-j`. **Ask the coordinator before every build or test task** (one ask covers the commands written in that task). Long jobs run in the background with the output redirected to a log under `$WT/build/` and the agent waits for the completion notice. Before every long macOS job run `sysctl vm.swapusage` and tell the coordinator if swap is in use. Never run a test binary directly (a hung one has no timeout); never run a build or test through git; no test or build step calls git.
- **Environment for renders** (this worktree has no `openrender/` deploy tree): the visual suite's build-tree paths, `SHADERS=$WT/build/shaders ORENDERHOME=$WT/build/tests/visual/_home DISPLAYS=$WT/build/src/display/file:$WT/build/src/display/rgbe:$WT/build/src/display/framebuffer GEOMETRIES=$WT/geometry`.
- **Remote** (Linux, GCC 13 `-Werror`): `SSH="ssh -o HostKeyAlias=ubuntu-2404-desktop.v2-labs.io juvenal@172.16.32.138"`, `R=/home/juvenal/Projects/Development/CLI/openrender-035`. Always a per-spec tree. **Never** touch `openrender`, `openrender-029`, `openrender-038` (nor `cellar`, `shrimp` or another spec's tree) on the host. Sync with `tools/sync_linux.sh` (written in Phase 0 from spec 057's, which refuses any `${R}` but the 035 tree and the forbidden ones). The sync never deletes: a removed file is removed by an explicit `$SSH "rm -f ${R}/<path>"` named in the task that removes it. Remote jobs: `$SSH "cd ${R} && CPUJOB_TIMEOUT=7200 ~/.claude/bin/cpujob 035-pN-lx-build cmake --build build -j2"` and `$SSH "cd ${R} && ~/.claude/bin/cpujob 035-pN-lx-test ctest --test-dir build -L closures -j2 --output-on-failure"`. In zsh a host-path pair is written `"${H}:path"` (`$H:path` is a modifier); the sync script uses `${R}` only.
- **Red-first**: a test that cannot compile yet lives in its own executable inside `if(OPENRENDER_035_RED_TESTS)` in `tests/closures/CMakeLists.txt` (default OFF, defined in Phase 1), so it never breaks the build or another test; its red evidence is the build failure naming the missing symbol, or a failing run. A test that is green on arrival (an acceptance test over code that already exists) is not red-evidenced, but its capability to fail is shown by a deliberate scratch breakage, reverted to an empty `git diff --stat` for the file and recorded.
- **Labels**: `closures` (the ABI and the BSDF), `closuremode` (modes, gate, surface step), `bxdf` (the statement and the built-ins), plus the existing `common`, `state`, `architecture`, `shading_parity`, `determinism-sweep`.
- **Test-local shaders** (probe surfaces and lights) live in `tests/closures/shaders/*.sl`, compiled as build steps (`.rslo` always, `.slo` with the JIT) into `$WT/build/tests/closures/shaders` as `tests/arealight/CMakeLists.txt` does. No file under `shaders/` changes (FR-027).
- **Formatting**: run `clang-format` with the repo's `.clang-format` on an edited source file **only if the file was clang-format clean before the edit** (check with `clang-format --dry-run` on the unedited file first); never reformat a file that was not clean.
- **Hooks**: the optional `speckit.git.commit` hooks (before and after tasks and implement) are declined. Nothing is committed, merged or pushed by an agent. `git add` is allowed; each checkpoint stages that phase's files.
- **Stops**: a **TEST-APPROVAL** task follows the red-evidence task of every phase that writes tests (Phases 1-5) and holds the phase until the maintainer approves the tests. A **PAUSE** is one named maintainer approval: the agent shows a diff (or a written proposal under `specs/035-closure-tree-bsdf/tools/proposed/`) and waits. Every change to an approved test, reference or image, and every `CLAUDE.md` text, is a PAUSE (a `CLAUDE.md` change is only ever a draft file, never an edit).
- **Never**: widen a tolerance or a threshold, disable a test to get a green result, edit an approved test or reference outside its PAUSE, re-capture an existing reference (SC-001; `git status --short tests src/libshader/tests` shows no changed file under a `reference` directory at any checkpoint), add a line to `tests/architecture/allowlist.txt` (FR-025), add an entry to the registry of `DEVNOTES_DETAILS/DOMAIN_BOUNDARIES.md`, name `CRenderer` or include `renderer.h` under `src/libshader`, edit a `.sl` file, edit the compiler (`src/libshader/compiler/`), edit anything under `src/ri/hiders/` (the 054 boundary, plan.md "Explicitly NOT modified"), write a task that depends on the merge, or put "Closes #41" anywhere but the maintainer's merge message (the text for it is drafted in the Phase 5 CLAUDE.md-draft task as a one-line note only).
- **Checkpoint architecture step**: every phase ends with `~/.claude/bin/cpujob 035-pN-arch ctest --test-dir $WT/build -L architecture --output-on-failure` (it must pass with `tests/architecture/allowlist.txt`, `ribvector-core-residual.txt` and `metrics-baseline.txt` unchanged: SC-009), then a CHECKPOINT task that stops for the maintainer's review and commit. Nothing of the next phase starts before the maintainer says so.
- **Records**: every checkpoint appends to `specs/035-closure-tree-bsdf/validation.md` (commands, counts, wall time of each job, what is still red and why) and stages the phase's files.
- **Interim rules** are named by their IDs (IR-017, IR-018, IR-026) in code, tests and the guide, never in a message's text (Q14).
