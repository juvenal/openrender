## Standing rules (apply to every task)

**Builds and tests (marked [RUN])**:
- The implementer asks the coordinator before each [RUN], then runs it through `~/.claude/bin/cpujob <label> <command>`:
  one job at a time machine-wide (spec 025's implement agent shares the lock), `nice -n 19`, at most `-j4`; the
  determinism sweep, the `texture_tile` label and #20's test use `-j2`.
- Long jobs go in the background with output redirected to `build-027-logs/<label>.log`. Wait for the completion notice.
- Never run a test binary directly (a hung one has no timeout). Never use `-j8`, a bare `-j`, or a count above 4.
- A plain `cmake --build` / `ctest` line below always means the `cpujob` form.

**Checkpoint procedure** (referenced as CP-a to CP-d by every phase's last task; commands in quickstart.md §2):
- **CP-a build**: `cpujob 027-pN-build cmake --build build-027 --config Release -j4`. It must be clean under `-Werror`.
- **CP-b suite**: stamp first (`specs/027-texture-system/tools/image_manifest.sh stamp build-027`), then
  `cpujob 027-pN-suite ctest --test-dir build-027 -LE determinism-sweep -j4 --output-on-failure`, and
  `cpujob 027-pN-tile ctest --test-dir build-027 -L texture_tile -j2 --output-on-failure`.
  - Expected: phase 1's pass list plus the tests enabled so far. The known-red tests above are the only allowed failures
    in Phases 2-8. Tests registered `DISABLED` show as "Not Run (Disabled)" and are not failures (verified once, by T037).
  - A red test from the known-flaky set (memory `reference_ctest_flaky_tests.md`: `ImagerRegressionRender`,
    `Parity_transparency-matte-aov`, `Parity_depthdefault`, `ShadingParity_AmbientAccumulation`) is re-run alone before it is
    written off. `ShadingParity_AmbientAccumulation` is a real heap bug: re-run it under the same conditions as phase 1 and compare.
- **CP-c architecture**: `cpujob 027-pN-arch ctest --test-dir build-027 -L architecture --output-on-failure`, plus the full
  report from `build-027/tests/architecture/archcheck --source-dir . --build-dir build-027 --config tests/architecture`.
  Record `ALLOWED`, `METRIC` and `RESULT` lines in validation.md.

**Thresholds and references**: never widen a threshold, never disable a test, never regenerate a reference image to get a green

**Red-first convention for tests that cannot compile yet**: a new test that needs an API that does not exist yet is added with
`EXCLUDE_FROM_ALL` on its executable **and** `set_tests_properties(<name> PROPERTIES DISABLED TRUE)` on its test, so the main
build and every checkpoint stay green.
- The red state is shown by `cmake --build build-027 --target <exe>` failing to compile; the error text goes in validation.md.
- The task that provides the API removes both markers, builds, and runs the test green.
- **`texturing_only_sources` and `TextureOnly_Standalone` are different** (T019): they compile `src/ri/texture` sources a second
  time on a narrow include path, so they are defined only when `OPENRENDER_TEXTURE_ONLY_TESTS` is on, **off by default until
  T092**. Their red evidence is taken in a scratch build directory with the option on (T034).
- Tests that compile only `tests/` sources against existing APIs (the T-J cases, `ShadingParity_JitPLDiagnosticsTexture`,
  `Display_RgbeBytes`) are normal, enabled registrations; their red state is by assertion or image difference.

**Mutation check**: every new test gets a scratch mutation at its green point (the edit is reverted and `git diff` confirmed
clean for that file; results in validation.md). The mutations are named in the tasks:

- T-S1 `ShadingParity_TextureSubstitute{,3D}`: drop an option field from `textureOptions()` (T082, T089);
- T-T1 `TextureOnly_Standalone`: perturb one lookup (T094);
- `TextureSystem_InfoMiss`: cache the `nullptr` of a miss (T063a); `TextureSystem_NullResolver`: drop the null check (T050a);
- `TextureSystem_ConcurrentFirstLoadExternalMutex`: its red is T-C1's, plus the re-entry assertion, whose death-style subtest is exercised once in a scratch Debug build (T071a);
- the characterization scenes (T030a): skip `commitTextureDraws()` in `lookupEnvironment()` (T080a); wrong `maxSolidAngle` accessor (T088a);
- T-D1 `Display_RgbeBytes`: change one codec byte (T043);
- `Common_StateOwnership`: keep `rgbe.cpp` in `ri_sources` so there are two definers (T043);
- T-C1 `TextureSystem_ConcurrentFirstLoad` and the T-J tests: their earlier red is the proof (T036, T035); T-J also gets
  two scratch mutations at Phase 9 (T106).

**No task depends on the merge**: no post-merge step, no merge hash, no GitHub comment. DB-026 moves to Resolved with "spec 027"
and the date its task is done. `Closes #33` and `Closes #20` are the maintainer's lines in the merge commit; not `Closes #97`.

**Stop conditions** (stop and report, never work around):
- a Texturing unit would need a Shading, Hiders, Graphics State or renderer-core header (T054);
- archcheck mishandles a doubly compiled Texturing unit (T095);
- a Phase 3-8 image or `MaxBlockAvgDiff` differs from the re-recorded baseline (T035a);
- the architecture check reports a new `VIOLATION`;
- any existing test result, `MaxBlockAvgDiff` or reference changes in Phase 9 (T109);
- spec 025 is not on master when T005a is reached (the maintainer decides; do not start the baselines on a tree that will change);
- T005a's merge reports a conflict other than `.specify/feature.json`, or master's allowlist differs from `bc261b1`'s by more than the DB-008 block;
- the self-deadlock hazard: `loadMutex` set to `&CRenderer::shaderMutex` while any services getter still holds it.

## Implementation strategy

**MVP is Phases 1-8.** After Phase 8, Texturing owns its texture system, depends on no other domain apart from the GI part left to spec 032 and the approved `retrieveDisplayChannel` forwarder, Shading reaches textures only through its services, the RGBE codec has one definer, and every render is byte-identical. That is the remediation this spec exists for (DB-026 resolved, DB-010 35 -> 8), and it unblocks specs 029, 032 and 048.

The rest is incremental:
- Phase 3 can ship alone (US4).
- Phase 9 makes `.slo` renders of `texture()`, `environment()` and `shadow()` match the interpreter, in isolation, so its output change is measured on its own and cannot hide a regression from the behaviour-preserving phases.
- Phase 10 updates the registry and docs, measures the time and the sweep, and hands the Linux validation to the maintainer.

Each phase leaves the tree green (apart from the compile-broken spans inside Phases 5 and 6, and the known-red T-J tests from Phase 2 to Phase 8), so any PAUSE is a safe stopping point.
