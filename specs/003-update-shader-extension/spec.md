# Feature Specification: Shader Extension Update (.sdr to .rslo)

**Feature Branch**: `003-update-shader-extension`  
**Created**: 2026-03-10  
**Status**: Draft  
**Input**: User description: "It's required to update the compiled shader filename extension convention used. This is the first step to prepare for integration with native LLVM compatible compilation, and add support for OpenShadingLanguage standard. The current compiled `object` RSL shader extension is `.sdr`. It should be changed to `.rslo`. The compiler should change to begin generating `.rslo` only, but it's required to keep compatibility with the old/current extension in the render load and execution side, following this protocol. It should try to load the new compiled extension `.rslo` and if unable to, try the old/current extension `.sdr`. If none were found, continue with the current implemented fallback or info/warning/error, as it's implemented currently."

## Clarifications

### Session 2026-03-10
- Q: How should the renderer handle an explicit .sdr extension in a RIB file? → A: Strip the .sdr extension and fall back to the standard search (.rslo then .sdr).
- Q: Should the shader compiler provide an override to still generate .sdr files if needed? → A: Yes, provide a CLI flag (e.g., --legacy-sdr) to allow manual override.
- Q: How should shader inspection tools (like sdrinfo) handle shader names without extensions? → A: Use the dual-extension search protocol (.rslo then .sdr).
- Q: Which search path mechanism should be used for the new .rslo extension? → A: Use existing SHADERPATH mechanism.
- Q: Should the renderer notify the user when falling back to a .sdr shader? → A: Yes, use standard renderer info/warning log.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Shader Compilation (Priority: P1)

When a developer compiles a RenderMan Shading Language (RSL) shader, the compiler produces a compiled object file with the new `.rslo` extension.

**Why this priority**: This is the primary requirement and enables the move toward LLVM/OSL compatibility.

**Independent Test**: Compile a sample `.sl` shader and verify that a file with the same base name and `.rslo` extension is created in the output directory.

**Acceptance Scenarios**:

1. **Given** a valid `.sl` shader source file, **When** the shader compiler is run, **Then** a `.rslo` file is generated.
2. **Given** a valid `.sl` shader source file, **When** the shader compiler is run, **Then** no `.sdr` file is generated by default.
3. **Given** a valid `.sl` shader source file, **When** the shader compiler is run with the `--legacy-sdr` flag, **Then** a `.sdr` file is generated instead of a `.rslo` file.

---

### User Story 2 - Renderer Shader Loading (Priority: P1)

When the renderer encounters a shader reference in a scene description (e.g., RIB file), it successfully locates and loads the compiled `.rslo` version of that shader.

**Why this priority**: Essential for using the new compiled format in production renders.

**Independent Test**: Create a RIB file referencing a shader that exists only as a `.rslo` file and verify the scene renders correctly.

**Acceptance Scenarios**:

1. **Given** a RIB file referencing "my_shader" and a compiled "my_shader.rslo" file, **When** the renderer is executed, **Then** the shader is correctly loaded and applied.

---

### User Story 3 - Backward Compatibility for Legacy Shaders (Priority: P2)

When the renderer cannot find a `.rslo` version of a requested shader, it automatically searches for and loads a `.sdr` version if available.

**Why this priority**: Critically important for maintaining compatibility with existing shader libraries and project assets.

**Independent Test**: Create a RIB file referencing a shader that exists only as a `.sdr` file and verify the renderer finds it and completes successfully.

**Acceptance Scenarios**:

1. **Given** a RIB file referencing "legacy_shader" and NO "legacy_shader.rslo" but a "legacy_shader.sdr" exists, **When** the renderer is executed, **Then** the `.sdr` file is loaded as a fallback and an informational message is logged.
2. **Given** both "shader.rslo" and "shader.sdr" exist, **When** the renderer is executed, **Then** the "shader.rslo" file is preferred and loaded.

---

### User Story 4 - Consistent Error Handling (Priority: P3)

When neither a `.rslo` nor a `.sdr` version of a shader is found, the system reports the missing shader according to established error handling rules.

**Why this priority**: Ensures the system remains predictable and provides helpful feedback when assets are truly missing.

**Independent Test**: Reference a non-existent shader in a RIB file and verify the output contains the expected warning or error message.

**Acceptance Scenarios**:

1. **Given** a RIB file referencing "missing_shader" where neither `.rslo` nor `.sdr` exists, **When** the renderer is executed, **Then** the standard "shader not found" error/warning is issued.

### Edge Cases

- **Mixed Extension Paths**: If a RIB file explicitly requests a `.sdr` extension (e.g., `Surface "plastic.sdr"`), the renderer MUST strip the extension and perform the standard search sequence (trying `.rslo` first, then `.sdr`).
- **Search Paths**: Ensure both extensions are searched for in all directories specified in the shader search path.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The shader compiler MUST be updated to use `.rslo` as the default output extension for compiled shaders.
- **FR-002**: The shader compiler MUST stop generating `.sdr` files by default.
- **FR-003**: The shader loading logic in the renderer MUST be updated to look for `.rslo` files first.
- **FR-004**: The shader loading logic MUST implement a fallback to `.sdr` if the `.rslo` version is not found.
- **FR-005**: Shader inspection tools (like `sdrinfo`) MUST implement the dual-extension search protocol (`.rslo` then `.sdr`) when a shader name is provided without an extension or with a legacy extension.
- **FR-006**: The system MUST search for both extensions across all directories in the `SHADERPATH` or equivalent environment variables.
- **FR-007**: The renderer and tools MUST automatically strip explicit `.sdr` or `.rslo` extensions from shader names in scene descriptions or command-line arguments before attempting to locate the compiled object file using the dual-extension search protocol.
- **FR-008**: The shader compiler MUST provide a command-line flag (e.g., `--legacy-sdr`) to allow users to force the output extension to `.sdr` for backward compatibility in specific build environments.
- **FR-010**: The renderer and shader tools MUST use the existing `SHADERPATH` (or equivalent) mechanism to locate both `.rslo` and `.sdr` files.
- **FR-011**: The renderer MUST log an informational message or warning when it falls back to loading a `.sdr` file because the `.rslo` version was not found.

### Key Entities

- **Compiled Shader**: The binary representation of a shader, now primarily identified by the `.rslo` extension (formerly `.sdr`).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of new shader compilations result in `.rslo` files by default.
- **SC-002**: 100% of existing `.sdr` shaders remain functional in the renderer without modification.
- **SC-003**: Shader loading time remains unchanged or within 5% of original performance (measuring the overhead of the double-look check).
- **SC-004**: All standard shader utility tools (e.g., `sdrinfo`) successfully report information for both `.rslo` and `.sdr` files.
