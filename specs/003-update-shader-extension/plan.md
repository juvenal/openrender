# Implementation Plan: Shader Extension Update (.sdr to .rslo)

**Branch**: `003-update-shader-extension` | **Date**: 2026-03-10 | **Spec**: [/Volumes/Projects/Development/CLI/openrender-sdr-change/specs/003-update-shader-extension/spec.md]
**Input**: Feature specification from `/specs/003-update-shader-extension/spec.md`

## Summary

The goal of this feature is to transition the compiled shader extension from `.sdr` to `.rslo` while maintaining backward compatibility. The shader compiler (`oshader`) will be updated to output `.rslo` by default, with a `--legacy-sdr` flag for backward compatibility. The renderer and shader tools will implement a dual-search protocol: attempting to load `.rslo` first, then falling back to `.sdr` with an informational log if the newer format is missing.

## Technical Context

**Language/Version**: C++20 / C17  
**Primary Dependencies**: Standard library, CMake, Flex/Bison (for shader parser)  
**Storage**: Filesystem (.sl, .sdr, .rslo, .rib)  
**Testing**: Integration tests in `tests/`, custom C++ tests  
**Target Platform**: Linux and macOS  
**Project Type**: CLI (orender, oshader, sdrinfo)  
**Performance Goals**: Shader loading time regression ≤ 5% (double-look check overhead)  
**Constraints**: POSIX conventions, standard Unix exit codes, no external dependencies without justification.  
**Scale/Scope**: Updating extension handling in compiler (`oshader`), renderer (`orender`), and inspection tools (`sdrinfo`).
