## Summary

Implement the RenderMan Interface Spec 3.2 `imager` shader type in openRender. The imager executes once per output pixel in `CRenderer::dispatch()` — after pixel filtering and before gamma/quantization and display driver dispatch — to allow shaders to modify final pixel color, opacity, and alpha. The compiler, parser, and display driver plugins require no changes (all support is confirmed present). Implementation touches four existing files and adds two new ones, all instrumented with `logging.hpp` at appropriate levels. Tests are written first per the TDD constitution mandate.

```cpp
void CRendererContext::RiImagerV(const char *name, int n,
                                  const char *tokens[], const void *params[]) {
    // WorldBegin guard (clarification Q3: warn + ignore).
    // inWorld is a new bool member of CRendererContext, set true in RiWorldBegin()
    // and false in RiWorldEnd(). No existing flag covers this; see research.md Decision 8.
    if (inWorld) {
        warning(CODE_NOTOPTIONS, "Imager \"%s\" specified after WorldBegin; ignored\n", name);
        log_warn("RiImager '{}' called after WorldBegin, ignored", name);
        return;
    }

    log_info("RiImager: loading shader '{}'", name);

    COptions *options  = getOptions(TRUE);
    CShaderInstance *s = getShader(name, SL_IMAGER, n, tokens, params);

    if (s == nullptr) {
        log_error("RiImager: shader '{}' not found; no imager will be applied", name);
        return;
    }

    if (options->imager != nullptr)
        options->imager->detach();

    options->imager = s;
    log_debug("RiImager: shader '{}' stored in options", name);
}
```

Note: preserve the existing `error()` call style for "not found" — `getShader()` already emits the canonical error; the `log_error()` is additive.

## Phase E: Execution Engine

### E.1 — `src/ri/imager.h`: `CImagerExecutor` Declaration (C++20)

```cpp
#pragma once
#include "../includes/logging.hpp"

class CShaderInstance;

class CImagerExecutor {
public:
    // Execute the imager shader over one pixel tile.
    // pixels: flat buffer, stride = sampleStride floats per pixel
    // Layout: [Ci.r, Ci.g, Ci.b, alpha, Z, ...]
    void execute(CShaderInstance &shader,
                 int left, int top,
                 int width, int height,
                 float *pixels,
                 int sampleStride) noexcept;
};
```

### E.2 — `src/ri/imager.cpp`: `CImagerExecutor` Implementation (C++20)

Key steps in `execute()`:

1. **Allocate variable arrays** for `numPixels = width * height`:
   - Use `std::vector<float>` for Ci (3×n), Oi (3×n), alpha (1×n), P (3×n)
   - Scalar arrays for ncomps, time, dtime (broadcast constant)

2. **Populate arrays from pixel buffer**:
   ```cpp
   for (int py = 0; py < height; ++py) {
       for (int px = 0; px < width; ++px) {
           int pidx = py * width + px;
           float *pix = pixels + pidx * sampleStride;
           ci[pidx*3+0] = pix[0]; ci[pidx*3+1] = pix[1]; ci[pidx*3+2] = pix[2];
           al[pidx]     = pix[3];
           oi[pidx*3+0] = oi[pidx*3+1] = oi[pidx*3+2] = pix[3]; // synthesized
           rp[pidx*3+0] = float(left + px) + 0.5f;
           rp[pidx*3+1] = float(top  + py) + 0.5f;
           rp[pidx*3+2] = 0.0f;
       }
   }
   ```

3. **Build varying[] pointer array** indexed by `VARIABLE_*` constants:
   ```cpp
   float *varying[MAX_VARIABLES] = {};
   varying[VARIABLE_CI]    = ci.data();
   varying[VARIABLE_OI]    = oi.data();
   varying[VARIABLE_ALPHA] = al.data();
   varying[VARIABLE_P]     = rp.data();
   varying[VARIABLE_NCOMPS]= nc.data();
   varying[VARIABLE_TIME]  = tm.data();
   varying[VARIABLE_DTIME] = dt.data();
   ```

4. **Execute shader**:
   ```cpp
   CMemPage *mem = nullptr;
   float **locals = shader.prepare(mem, varying, numPixels);
   shader.execute(nullptr, locals);   // null context: imager has no surface built-ins
   ```

5. **Write back Ci and alpha**:
   ```cpp
   for (int i = 0; i < numPixels; ++i) {
       float *pix = pixels + i * sampleStride;
       pix[0] = ci[i*3+0]; pix[1] = ci[i*3+1]; pix[2] = ci[i*3+2];
       pix[3] = al[i];
   }
   ```

6. **Logging** (additive, not replacing existing paths):
   ```cpp
   log_debug("imager execute: tile ({},{}) {}x{} ({} pixels)", left, top, width, height, numPixels);
   // ... after execute ...
   log_debug("imager execute: tile done");
   ```

## Performance Validation (SC-004)

SC-004 requires ≤5% frame-time overhead when an imager shader is active relative to no-imager rendering.

**Methodology**: Manual profiling via wall-clock comparison of two renders of the same scene (identical geometry, lighting, image dimensions) — one with `Imager "background"` and one without. The imager adds one `executeChunk()` call per dispatch bucket, which copies pixel data into the shading state's pre-allocated varying arrays, runs the shader VM, and copies results back. For a trivial background shader (3 arithmetic ops per pixel) on a 512×512 image with 16×16 buckets, the per-bucket cost is O(256 × 3 ops) ≈ negligible relative to shading.

**Acceptance**: If any production render shows >5% overhead due to imager execution, the fix path is: (a) skip `executeChunk` for buckets where all pixels are fully opaque (alpha=1, Oi=1), or (b) batch multiple shading states per chunk call. No timing infrastructure is added to the test suite; SC-004 is verified post-ship by manual profiling.
