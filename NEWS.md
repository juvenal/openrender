# News

## Unreleased

- (2026-11-11) Hiders and integrators are chosen through registries, and a new `Integrator` statement selects the integrator a frame is rendered with (spec 030, GitHub #36). `Integrator "classic"` (RIB, `RiIntegrator`/`RiIntegratorV` in the C API, and `Integrator` in the Python and Lua helpers; `classic` is the default and changes nothing) takes optional parameters, preview and `ribOut` carry the statement, and an unknown name is reported with the registered names and falls back to `classic`. A hider declares what it provides (`rasterization`, `display-output`, `display-channels`, `deep-shadow-output`, `illumination-hook`) and an integrator what it requires and may use; a pair that does not fit is refused with one error naming the hider, the integrator and the shortfall, the frame is not rendered, no file is written and `orender` exits -1. A parameter the integrator does not define is now an error (`Integrator "<name>" does not define parameter "<p>"; ignored`; the frame still renders and `orender` exits -1, like an unknown `Option`). The renderer core no longer names a concrete hider (`strcmp` chains, `dynamic_cast` and the `hiderFlags` description bits are gone), and the hard-coded C++ lights `spherelight` and `quadlight` (`hcshader`) are retired: **behaviour change**, a light named `spherelight` or `quadlight` with no compiled shader on the shader path now reports `Failed to find shader "<name>"` like any other missing shader, where the C++ substitute used to answer (with the shipped RSL shaders on the path no image changes; every image of the test suite is byte-identical on macOS and Linux). The hider and integrator table interfaces (version 2.0.0) are internal until spec 051.
- (2026-11-04) The Scene Interface (the RIB parser, the RIB writer and the `RiBegin` dispatch) no longer depends on the renderer core (spec 038, GitHub #43). Visible changes: (1) reports raised while the renderer context is constructed (for example "Failed to connect to ..." when a network render cannot reach a server) now reach the diagnostic sink installed before `RiBegin` and no longer set `RiLastError`; their text, stream and severity are unchanged, and, as a result, a failed network connect (`Failed to connect`, `Failed to resolve`, `Version mismatch with server`) no longer makes `orender` exit with -1; (2) a `.slo` shader can call a DSO shadeop operand: `oshader --jit` compiles the call and the renderer binds the operand when it loads the shader (a module with such a call records the `.slo` format 2.1.0, every other `.slo` still records 2.0.0; a missing operand makes the renderer fall back to the `.rslo`, which reports it as before); (3) `libRIBVector` no longer exports the symbols of `rendererClipping.cpp` and `resource.cpp`; (4) `RiBeginLite` is removed from `rib.h`, replaced by `RiBeginBackEnd`/`RiEndBackEnd` and `RiRegisterBackEnd` in `riHooks.h`, and `riHooks.h` moved to `src/ri/parse/`; (5) a RIB-writer, preview or data-viewer file lookup made after a renderer session in the same process now finds a bare file name that exists only in the working directory (the renderer left its temporary-directory path set after `RiEnd`, GitHub #136, which this change does not fix). The shader compiler now owns its builtin function and opcode tables (`src/libshader/compiler/builtinTables.cpp`, generated, with a drift test) and `precomp` includes only a constants header.
- (2026-11-03) The interpreter's void shader DSO operands (a shadeop declared `void name(...)`) now step varying arguments correctly: each operand argument advanced four times too far per point, so a void operand called with a varying argument read past the argument array and received wrong values for every point after the first. Value-returning operands were not affected. Found while giving the JIT (`.slo`) its DSO call path, whose void operands read the right values.

- (2026-10-31) Plug-in interfaces are versioned (spec 037). Display drivers, shader DSO operands and the procedural modules each declare a `MAJOR.MINOR.PATCH` interface version, and the renderer checks it before it calls anything in the module: a supported MAJOR loads, a newer MINOR loads with one warning, any other MAJOR is rejected with a clear error instead of crashing. **Display 2.0.0** replaces the callback interface with a function table, a per-display context, a read-only parameter snapshot, channel descriptors and a documented threading contract (a driver can no longer overwrite the renderer's clip planes, matrices or another display's quantizer); drivers written for the old interface (MAJOR 1) keep working through an adapter, with two differences: writes through the pointers the old parameter callback returned no longer reach the renderer, and `displayRawData` is ignored. **Shadeop 1.1.0** adds optional per-thread init and cleanup for shader DSO operands, a new `libRIBShadeop` library carries the one declaration parser and scan the renderer and `oshader` now share, and the dlo, implicit and `DynamicLoad` interfaces are declared at 1.0.0 behind one procedural module that loads a bare module name from the procedural search path and unloads a `DynamicLoad` generator only after its geometry is gone. Plug-ins without a version symbol still load (as 1.0.0) with one warning, and **will be rejected from openRender 1.2.0**. `file_base.h` (the base class of the in-tree file drivers) is no longer installed; third-party authors start from `examples/display/simpledisplay.c`. `RiDisplay` parameters of type `double`, `quad` and `mpoint` are now dropped with a warning. The public headers install into `<ORENDERHOME>/include` (self-contained) or the `openRender` subdirectory of the include directory (FHS), and `find_package(openRender)` supplies the path. See [PLUGIN_ABI.md](DEVNOTES_DETAILS/PLUGIN_ABI.md) and [DISPLAY_PLUGIN_GUIDE.md](DEVNOTES_DETAILS/DISPLAY_PLUGIN_GUIDE.md).

## Latest (1.0.0)

openRender 1.0.0 is the first release under the openRender name, rebranded from Pixie. It includes:

- CMake-based build and install
- Documentation converted to Markdown (README, INSTALL, LICENSE, AUTHORS, etc.)
- Semantic versioning (MAJOR.MINOR.PATCH)

For a detailed list of changes, see [ChangeLog.md](ChangeLog.md).

## Since 5399a1b (2025-08-27 – 2026-02-10)

- (2026-10-28) Under the JIT (`.slo`), `texture()`, `environment()` and `shadow()` now match the interpreter: they honour their optional parameter lists (`blur`, `width`, `swidth`, `twidth`, `fill`, `samples`, `filter`, `bias`), use the filtered footprint, write all three channels of the color forms, and `environment("raytrace")`/`shadow("raytrace")` trace as they do under the interpreter. A shader's own parameter or local now shadows a built-in variable of the same name under the JIT, and `textureinfo()` returns its result correctly. A `.slo` compiled before must be rebuilt (the old entry points are removed and such a shader fails to bind). The texture state moved into a per-frame texture system and the RGBE codec into `libRIBCommon`; `.rslo` renders are unchanged.
- (2026-10-01) `cmake --install` now ships `libRIBOut` (RIB text output), which was built but never installed. All three RenderMan Interface libraries share one naming scheme and come in shared and static form: `libRIBRender`, `libRIBVector`, `libRIBOut`. The old names (`libri`, `libribVector`, `libribOut`) remain as compatibility symlinks. Installing shaders now prints one summary line per group (sources, headers, `.rslo`, `.slo`) instead of a line per file. Staged (`DESTDIR`) installs no longer write outside the staging root, and every installed static archive now links standalone in an external project. External CMake projects can use `find_package(openRender)` and link `openRender::RIBRender` (or `openRender::RIBRender_static` with `COMPONENTS Static`).
- (2026-08-10 – 2026-08-13) Hardened Catmull-Clark subdivision surface support into full RISpec conformance: fixed a facevarying data-loss bug where per-corner UV-seam values silently collapsed on any vertex shared by more than one face; added the `facevaryinginterpolateboundary`, `facevaryingpropagatecorners`, and `creasemethod` subdivision tags (previously unrecognized/hard errors); added `RiHierarchicalSubdivisionMesh` (per-face, per-level tag overrides layered on a base subdivision mesh) across RIB grammar, the RI entry point, the renderer, RIB round-trip output, the `orender-wire` previewer, and the Lua binding; added the Loop subdivision scheme as a second scheme alongside Catmull-Clark; investigated (but did not reproduce) reported crease-quality issues, with the negative result documented for future reference. Cross-hider coverage (REYES, raytrace, photon) verified via an expanded 75-scene visual regression suite (up from 33) plus a 25-scene parity suite, all passing, with a grep-verified invariant that no hider file contains subdivision-specific code. See [SUBDIVISION_SURFACES.md](DEVNOTES_DETAILS/SUBDIVISION_SURFACES.md).
- (2026-06-07 – 2026-07-08) LLVM JIT shading engine: `oshader --jit` now compiles RSL shaders to LLVM bitcode (`.slo`), executed natively at render time via LLJIT. The compiler and interpreter runtime are extracted into a new `src/libshader/` library hierarchy. New `sloinfo` binary auto-detects `.slo` vs `.rslo` format. Shader format selection added at three levels: `Attribute "shade" "shaderformat"` (per-primitive), `Option "shaderformat" "default"` (scene-wide), and `OPENRENDER_DEFAULT_FORMAT` env var (compile-time fallback). Structured logging via `ORENDER_INSTR_LEVEL`/`ORENDER_INSTR_OUTPUT` environment variables. Eight `cellnoise` ops added to the JIT emitter. Coordinate transforms (`vtransform`, `ntransform`, `ptransform`) corrected. `lightTags` fix prevents non-illuminated vertices from receiving spurious light contributions in the JIT path. Shader-space parameter defaults at bind time fixed via `jitSetInitXform` thread-local fallback (`somewood` vein orientation). Visual regression suite expanded to 43 scenes, including `.slo` JIT parity tests.

- (2026-05-31) Fixed a shader compiler bug where the CSE optimizer shared its expression cache across all IR basic blocks, causing constant loads inside if/else branches to silently corrupt subsequent code. The regression was visible in `windowhighlight.sl` (sphere highlight shape wrong vs. PRMan 3.9). CSE is now intra-block only. Separately, the `oshader` compiler now rejects `Ps` (the illuminated surface point) inside surface shaders — it is only defined in light shaders per RI Spec. Scope enforcement is backed by a new per-variable scope mask checked on every built-in variable lookup.

- (2026-05-28) Fixed the imager shader pipeline to match the RenderMan spec (Render → Exposure → Imager → Quantize). Exposure is now applied in `CRenderer::dispatch()` before the imager shader runs, so imager shaders correctly receive post-exposure color and coverage values. All four file-format display plugins (TIFF, PNG, OpenEXR, RGBE) are refactored to share a common base class (`CFileOutputBase`) that handles scanline accumulation, thread safety, quantization, and dither; `file_base.h` is now installed for third-party display plugin authors.
- (2026-05-27) Python (`prman.py`) and Lua (`prman.lua`) language bindings are now proper install targets. Both are installed under `python/` and `lua/` in self-contained builds, or under `share/openRender/{python,lua}/` in FHS installs. Destinations can be customized at configure time with `-DOPENRENDER_PYTHONDIR` and `-DOPENRENDER_LUADIR`.
- (2026-05-27) Overhauled the build system for distribution-quality output: `libri.a` and `librslo.a` static archives are now installed alongside their shared counterparts; shared libraries carry proper `VERSION`/`SOVERSION` metadata; executables embed RPATH for relocatable installs; and self-contained builds automatically bundle external dependencies (libtiff, libpng, OpenEXR, etc.) with correct `@rpath`-relative IDs on macOS.
- (2026-05-19–2026-05-24) Added `orender-wire`, an interactive RIB wireframe scene previewer shipping as a native Metal/AppKit application on macOS and a GTK 4/OpenGL binary on Linux. Built on `libribpreview`, a new static library that tessellates all RenderMan primitive types into a flat line-list with per-vertex surface colors. Includes a full arcball camera, camera export/replace, and a 9-tessellator test suite. Decoupled from the full renderer — works without `ORENDERHOME`, `SHADERS`, or `DISPLAYS`. Removed the legacy `src/gui/` Qt/FLTK directory.
- (2026-05-19) Completed the full rename of the shader subsystem from `sdr` to `rslo`, including internal directories, library names (`librslo`), and tool names (`rsloinfo`). Unified RIB output initialization and added standard compliant preamble headers to all RIB generated by C++, Python, and Lua interfaces.
- (2026-03-10) Updated the compiled shader extension from `.sdr` to `.rslo`. The `oshader` compiler now outputs `.rslo` by default, while maintaining full backward compatibility for existing `.sdr` shaders. Added `--legacy-sdr` flag to `oshader`.
- (2026-02-08–2026-02-10) Completed the openRender rebrand, added speckit tooling, rewrote the README, and introduced Geometry RIB statement support with updated geometry definitions.
- (2026-01-02–2026-01-04) Added new shaders, RIB examples (including the Utah Teapot and wood materials), custom geometry, and NSI documentation references.
- (2025-12-27–2025-12-31) Simplified math macros, enhanced versioning and path handling, and refreshed shader assets and `.gitignore` entries.
- (2025-12-12–2025-12-16) Migrated documentation to a Hugo-based site with a dedicated theme, CI-based deployment, and updated configuration.
- (2025-12-07–2025-12-08) Modernized the codebase for C++20/C17 with improved 64-bit portability and portable I/O for photon maps, point clouds, and deep shadow maps; standardized formatting and documentation across core components.
