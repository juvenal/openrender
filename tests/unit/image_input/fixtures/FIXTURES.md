# Fixture provenance and exact expected values (T004)

Two sizes per format, both with deterministic, closed-form per-pixel
formulas so decoder unit tests can assert exact expected content, not just
"decoded without crashing":

- **`tiny_*`** (4x4): fast, hand-verifiable exact-value assertions.
- **`large_*`** (512x512): realistic-scale coverage — a 4x4 image is
  smaller than `otexmake`'s `DEFAULT_TILE_SIZE` (32, `src/ri/core/
  ri_config.h:31`), so it barely exercises tiling or the mip-pyramid
  reduction in `appendPyramid()`; 512x512 gives 16x16 tiles per level and a
  full 10-level mip pyramid (512→...→1), and stands in for daily-usage
  texture sizes for the bake-regression (T006) and visual-regression
  (T014/T020/T026) tests.

Generated by scratch scripts (not checked in — the formulas below fully
reproduce them): Pillow + numpy for TIFF/PNG, a small standalone OpenEXR/
RGBE C++ program for the rest. All formulas use `fx(x) = x/(W-1)`,
`fy(y) = y/(H-1)` (both in `[0,1]`), so the same bounded value ranges apply
at either size — a fixture generated at any W,H is reproducible from these
formulas alone.

## TIFF / PNG — `{tiny,large}_*`, for x,y in `[0,W-1]x[0,H-1]`

- `{}_rgb.tif`, `{}_rgb8.png`: R(x,y) = (3x+10) mod 256, G(x,y) = (5y+20) mod 256, B(x,y) = (x+2y+30) mod 256
- `{}_rgba8.png`: RGB as above, A(x,y) = (7x+11y+40) mod 256
- `{}_gray8.png`: L(x,y) = (x+y) mod 256
- `{}_gray_alpha8.png`: L(x,y) = (x+y) mod 256, A(x,y) = (7x+11y+40) mod 256
- `{}_gray16.png`: 16-bit grayscale, L(x,y) = (97x + 131y) mod 65536
- `{}_indexed.png`: palette-indexed (negative-test fixture — must be
  rejected, not decoded); palette[i] = (i, 255-i, 3i mod 256), pixel
  index(x,y) = (x + y*W) mod 256

## OpenEXR — `{tiny,large}_*`, for x,y in `[0,W-1]x[0,H-1]`

Common per-pixel base values (float), with `fx`/`fy` as defined above:
- R(x,y) = 0.1 + 0.4·fx(x) + 0.1·fy(y)
- G(x,y) = 0.2 + 0.3·fx(x), **+2.5 at (0,0) only** (deliberately exceeds
  1.0, to prove decode does not clamp)
- B(x,y) = 0.3 - 0.2·fx(x) - 0.1·fy(y)
- A(x,y) = 0.5 + 0.4·fx(x)

Files:
- `{}_rgb.exr`: channels R,G,B (FLOAT) = above
- `{}_rgba.exr`: channels R,G,B,A (FLOAT) = above
- `{}_luminance.exr`: single channel "Y" (FLOAT), Y(x,y) = 0.4 + 0.4·fx(x) + 0.2·fy(y)
- `{}_half.exr`: channels R,G,B (HALF) = above, cast through `half` —
  expect promoted `bitsPerSample == 32` on decode, values equal to the
  above within half-precision rounding (~3 significant digits)
- `{}_unsupported_channels.exr`: channels R,G,B,Z (FLOAT), Z(x,y) = 10+fx(x)
  — negative-test fixture, must be rejected (not RGB, not RGBA, not
  single-channel)
- `{}_multipart.exr`: 2 parts ("part0": R,G,B as above; "part1": same
  +1.0 each) — negative-test fixture, must be rejected unconditionally
  regardless of content, per spec.md's clarified scope

## RGBE — `tiny.hdr`, `large.hdr`

Radiance HDR, no RLE, header `#?RGBE` / `FORMAT=32-bit_rle_rgbe` /
`-Y H +X W`. Pixel values are R(x,y)/G(x,y)/B(x,y) from the OpenEXR
formulas above, run through the standard RGBE shared-exponent encoding
(`float2rgbe`, mirrored from `src/display/rgbe/rgbe.cpp`). Decode is
lossy (shared 8-bit exponent + 3x8-bit mantissa) — tests should compare
with a relative tolerance of ~0.5% (1/256), not exact equality.
