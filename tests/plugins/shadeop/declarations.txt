# Spec 037, ShadeopAbi_DeclarationCharacterization: the starting tree's dsoParse over about 40 declarations.
#
# One case per line: <declaration> TAB <1 if accepted, 0 if rejected> TAB <name> TAB <prototype>.
# The declaration field uses escapes: \t tab, \n newline, {empty} the empty string, and {rep:N:text} N copies
# of text. A rejected case has empty name and prototype fields.
#
# The prototype is the return type letter, '=', then one letter per parameter
# (o f v n p c m s for void float vector normal point color matrix string). The parameter names and the
# word 'output' do not appear in it.
#
# ORDER MATTERS. The old parser keeps its prototype in a static 256-byte buffer that it never
# terminates: a declaration shorter than the one before it returns the new prototype followed by the
# stale tail of the old one (measured: see the observation line the test prints). The cases are therefore ordered by increasing prototype length, and the
# rejected ones (which can leave a partial prefix) come last. No case has a prototype of more than 255
# letters (the buffer is unbounded). Unknown characters ($, ;) are echoed to stdout by flex and skipped.
